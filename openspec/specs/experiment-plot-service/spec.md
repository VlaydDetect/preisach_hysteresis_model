# experiment-plot-service Specification

## Purpose

Позволяет приложению C++ передать готовый результат локальному Python-серверу для автоматического построения графиков.

## Requirements

### Requirement: Отправка сохранённого архива включается явно

По умолчанию C++ MUST работать с отключённой отправкой. При её включении клиент MUST отправлять байты завершённого архива с диска и сообщать состояние доставки отдельно от состояния сохранения.

#### Scenario: Запуск по умолчанию

- **WHEN** оператор запускает эксперимент без включения отправки
- **THEN** C++ сохраняет архив без попытки сетевого подключения

#### Scenario: Передача не подтверждена

- **WHEN** сервер недоступен, соединение оборвалось или подтверждение не пришло в срок
- **THEN** клиент сообщает об ошибке доставки и указывает путь к пригодному для офлайн-отрисовки архиву

### Requirement: Сервер принимает архив целиком

Сервер MUST принимать один архив на TCP-соединение и подтверждать успех после получения, проверки и сохранения полного архива. Сервер MUST ограничивать объявленный размер и время сетевых операций.

#### Scenario: Данные поступают частями

- **WHEN** длина и содержимое архива переданы произвольными TCP-фрагментами
- **THEN** сервер собирает точно заявленное количество байтов, сохраняет идентичный архив и подтверждает приём

#### Scenario: Передача оборвалась или объявленный размер превышен

- **WHEN** клиент не передаёт полный архив, либо заявленная длина выходит за допустимые пределы
- **THEN** сервер завершает попытку, исключает частичный файл из доступных результатов и продолжает принимать подключения

#### Scenario: Архив не прошёл проверку

- **WHEN** сервер получает все заявленные байты, но загрузчик отклоняет содержимое
- **THEN** сервер сообщает об ошибке приёма без публикации архива и без отрисовки

### Requirement: Сетевой и офлайн-запуск строят графики одинаково

Сервер MUST передавать сохранённый результат тому же загрузчику и обработчикам графиков, что используются при открытии архива с диска. Приём следующих запусков MUST продолжаться, пока оператор просматривает предыдущий график.

#### Scenario: Два последовательных запуска

- **WHEN** два запуска C++ отправляют результаты одному экземпляру сервера и окно первого графика остаётся открытым
- **THEN** сервер принимает и сохраняет оба архива, а графики каждого используют его данные и параметры оформления

#### Scenario: Повторное открытие принятого архива

- **WHEN** оператор открывает принятый архив с диска
- **THEN** отрисовка получает те же массивы, вид графика, заголовок и подписи, что и при сетевом запуске
