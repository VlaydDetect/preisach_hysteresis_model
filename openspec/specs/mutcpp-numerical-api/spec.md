# mutcpp-numerical-api Specification

## Purpose

Определяет численные типы публичного API MUTCpp и гарантии времени жизни моделей и систем, доступных его потребителям.

## Requirements

### Requirement: Eigen представляет численные данные MUTCpp

Публичные численные интерфейсы MUTCpp MUST использовать Eigen для матриц, векторов и массивов коэффициентов, когда Eigen поддерживает требуемое представление. Публичные заголовки MUST подключаться с объявленными зависимостями независимо от порядка включения заголовков в драйвере экспериментов.

#### Scenario: Подключение заголовка

- **WHEN** потребитель включает `MUTCpp.hpp` или отдельный затронутый публичный заголовок в минимальной единице трансляции
- **THEN** компиляция проходит с объявленными зависимостями и без заголовков удалённых типов

#### Scenario: Вызов численного алгоритма

- **WHEN** потребитель передаёт матрицу, вектор или массив в перенесённый численный интерфейс
- **THEN** потребитель использует поддерживаемый тип Eigen без промежуточного контейнера MUTCpp

### Requirement: Сохранение функций без прямого эквивалента

MUTCpp MUST сохранять публичные алгоритмы, для которых Eigen не предоставляет прямого эквивалента по входам, результату и значимым граничным случаям, за исключением кодека Hamming SECDED. Наличие вызова в драйвере экспериментов MUST NOT определять доступность такой функции.

#### Scenario: Уникальная функция без вызовов в приложении

- **WHEN** C++-потребитель вызывает сохранённый алгоритм без прямого эквивалента в Eigen, который не используется опытами в репозитории
- **THEN** алгоритм доступен через публичный интерфейс и сохраняет существенную семантику результата

#### Scenario: Кодек Hamming SECDED удалён

- **WHEN** потребитель подключает публичные заголовки MUTCpp
- **THEN** заголовки не предоставляют `mc::edac::encode` и `mc::edac::decode` для Hamming SECDED

### Requirement: Контракт границ фильтра пиков

`find_peaks` MUST поддерживать отсутствие границ, одну нижнюю границу и пару границ. Операция MUST сохранять действующие правила включения границ. Публичный контейнер `StaticVector` MUST оставаться доступным.

#### Scenario: Задание границ на месте вызова

- **WHEN** потребитель опускает фильтр, задаёт одну границу или задаёт обе границы
- **THEN** он получает результат без фильтра, с односторонним фильтром или с двусторонним фильтром соответственно, в том числе при совпадении свойства пика с границей

### Requirement: Копирование аргументов сохраняет экземпляр модели

Копии аргументов одной траектории MUST сохранять совместное владение экземпляром модели Прейзаха этой траектории. Уничтожение или замена одной ссылки MUST оставлять модель живой, пока существует другой владелец.

#### Scenario: Копирование и замена аргументов

- **WHEN** потребитель копирует аргументы, затем заменяет модель в одной копии
- **THEN** другая копия сохраняет прежний экземпляр и его накопленное состояние, а новая модель остаётся доступна через изменённую копию

### Requirement: Стандартное владение объектами

Публичные владельцы объектов MUST использовать стандартные умные указатели согласно семантике владения. Код MUTCpp и его потребители в проекте MUST обходиться без `mc::Ref`, `RefCounted` и `WeakRef`.

#### Scenario: Освобождение объектов

- **WHEN** потребитель освобождает последнего владельца системы или полиморфной модели
- **THEN** деструктор фактического объекта и деструкторы принадлежащих ему компонентов выполняются по одному разу

#### Scenario: Режим сборки с профилированием памяти

- **WHEN** сборка с профилированием использует глобальные переопределения выделения памяти и потребитель создаёт и освобождает объекты стандартными умными указателями
- **THEN** операции сохраняют требуемое выравнивание и корректно освобождают память

### Requirement: Численные алгоритмы возвращают типизированные результаты

АЧХ, спектр Фурье, диаграммы бифуркаций и затронутые вычисления Ляпунова MUST предоставлять результаты через типизированный численный API. Потребитель MUST иметь доступ к численным данным без сериализации.

#### Scenario: Прямое использование результатов вычисления

- **WHEN** C++-потребитель вычисляет спектр или диаграмму бифуркаций
- **THEN** он получает численные ряды и связанные параметры с определёнными типами, формами и порядком отсчётов

### Requirement: JSON-адаптеры поддерживают численные и предметные значения

Для поддерживаемых экспортируемых типов Eigen и MUTCpp, требующих явного преобразования, библиотека MUST предоставлять отдельные JSON-адаптеры. Адаптеры MUST определять представление формы и обработку значений, для которых у JSON отсутствует числовое представление.

#### Scenario: Экспорт представления Eigen

- **WHEN** C++-потребитель передаёт поддерживаемый вектор, матрицу или выражение Eigen в JSON-адаптер
- **THEN** JSON содержит элементы в логическом порядке, а массивы с неоднозначной формой содержат данные, необходимые для её восстановления

#### Scenario: Экспорт геометрии конуса

- **WHEN** C++-потребитель экспортирует геометрию конуса через предметный адаптер
- **THEN** JSON содержит размерность, лучи и данные кривой, нужные поддерживаемому сценарию чтения
