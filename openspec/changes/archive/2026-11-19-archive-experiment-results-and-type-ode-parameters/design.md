# Design

## Context

`JsonDocument` дублирует имена полей в `header` и меняет ранг массива в зависимости от `Eigen::isFlat`. АЧХ, спектр Фурье и часть анализов ODE создают JSON внутри расчёта. `DynamicalSystem<N>` хранит текущие и исходные словари для двух траекторий. В правой части Радонса словарь читается на каждой стадии RK4 и модель изменяет историю. В `JustSolveRodos` уже создаются две независимые модели.

`Net::Server` в C++ выполняет роль клиента. Его вызовы отправки в драйвере закомментированы. Python-сервер делает один `accept()` и декодирует каждый `recv()` как отдельный документ. Офлайн-графики читают файлы напрямую через `python/main.py`. Два крупных сохранённых результата, `BifurcationDiagram_A.json` и `RodosLCEs_DivergenceDegreeTable.json`, занимают примерно 576 и 439 МиБ.

## Goals / Non-Goals

**Цели** — сохранить численную семантику и сделать совместный артефакт сохранения, доставки и отрисовки. Проверять схему параметров до вычисления и владение изменяемой моделью на границе системы.

**Граница** — архив фиксирует данные графиков. Возобновление интегрирования из внутреннего состояния модели, удалённый сервис и произвольные команды отрисовки лежат за пределами изменения.

## Decisions

### Архив эксперимента

Использовать один `.zip` с `manifest.json` в UTF-8 и именованными `arrays/<id>.npy`. ZIP позволяет хранить и пересылать один файл, а Python может читать его записи через стандартный `zipfile`. Папка удобна при разработке, но требует отдельной упаковки для передачи. NPZ предназначен для коллекции массивов, а здесь JSON-манифест является самостоятельной частью контракта. Первая версия использует ZIP-записи без сжатия и потоковую запись на стороне C++. Готовая ZIP-библиотека в слое приложения предпочтительна для записи каталога и контрольных сумм. [Python zipfile](https://docs.python.org/3/library/zipfile.html), [Формат NPY](https://numpy.org/doc/stable/reference/generated/numpy.lib.format.html)

`manifest.json` содержит `schema_version`, `experiment_kind`, снимок доступных параметров эксперимента, именованные массивы с семантикой осей и список `plots`. Имя массива однозначно задаёт путь внутри ZIP. Для каждого графика хранить `kind` и необязательные строки `title`, `x_label`, `y_label`. Требуемые наборы массивов определяет зарегистрированный вид графика. Пустой список допустим для артефакта без запрошенной отрисовки. Серверу достаточно таблицы зарегистрированных обработчиков.

NPY описывает форму, тип элементов и порядок хранения. Строки и столбцы экспорта должны соответствовать контракту метода при любом размещении данных в Eigen. Вектор записывается как одномерный массив, если поле имеет семантику ряда. Матрица сохраняет две оси, даже если одна из них имеет длину 0 или 1. Сохранять `double` без понижения точности, поддерживая численные типы, реально используемые экспортом. Временной ряд задавать фактическими отсчётами. Для `JustSolveRodos` проверить число отсчётов по данным решателя, поскольку старые серверный и файловый пути по-разному интерпретируют поля времени.

C++ пишет архив во временный файл рядом с конечным, закрывает его и публикует переименованием по новому имени, чтобы уже сохранённый запуск нельзя было затереть. Сетевой режим получает только путь к опубликованному файлу. Python открывает ZIP как контейнер без распаковки по путям из архива. Загрузчик сверяет идентификаторы записей, размеры, контрольные суммы, заголовки NPY и формы с ожидаемыми данными до выделения памяти для больших массивов. Численные массивы читаются без pickle.

### Численный API и JSON

Отделить результаты вычислений от кодека. АЧХ, спектр Фурье, бифуркации и затронутые расчёты Ляпунова возвращают предметные типы с Eigen и скалярами. Использовать существующие структуры результатов там, где они покрывают семантику, например структуру экстремумов диаграммы бифуркаций. Драйвер переводит эти результаты в содержимое архива. Публичные JSON-операции вынести в отдельные заголовки.

Нативные типы и поддерживаемые контейнеры передавать в `nlohmann::json` напрямую. Для Eigen использовать явное преобразование по логическим индексам для плотных векторов, матриц, массивов и используемых выражений, включая столбец траектории. Для предметных типов, например геометрии конуса и экспортируемого представления функций Эверетта, держать небольшие адаптеры рядом с границей JSON. При неоднозначной форме кодировать её явно. Для обычных обязательных чисел JSON сообщать об ошибке при нечисловом или бесконечном значении. Пропуски кодировать как `null` только в полях с таким контрактом. В численных NPY-данных сохранять исходные значения. Текущие поля старого JSON трактует адаптер чтения для этого формата. [Преобразования типов nlohmann/json](https://json.nlohmann.me/features/arbitrary_types/)

### Параметры и два контекста системы

Параметризовать семейство `DynamicalSystem<N, Context>` / `ContinuousDS<N, Context>` типом контекста. Типы `LorenzParams`, `DuffingParams` и `RadonsParams` содержат параметры уравнений. Контекст хранит эти значения и изменяемые объекты конкретной траектории. RK4, правая часть, якобиан и операции сброса работают с соответствующим контекстом. Общие алгоритмы выводят тип системы, а двумерные и трёхмерные алгоритмы сохраняют ограничения по размерности. Вариант с типизированными параметрами в захватах лямбд оставляет скрытое состояние при обновлении, восстановлении и парном вычислении, поэтому контекст передаётся явно.

Хранить обязательный основной и явно заданный возмущённый контексты. Для парных операций без второго контекста возвращать ошибку. Операции создания, обновления и восстановления пары проверяют различие экземпляров Прейзаха перед установкой новых значений. Сброс одной модели изменяет только её историю. Копия контекста сохраняет `shared_ptr` на модель этой траектории. Существующий `SystemState` переносит типизированные значения и совместное владение, поэтому сохранение и восстановление такого снимка сохраняет идентичность живой модели.

Разделить текущие значения и значения по умолчанию через явные операции. При переносе вызовов отдельно проверить замену моделей в callbacks и места, где `SetArgs(..., keepAsDefault)` сейчас обновляет исходные значения независимо от флага. Сохранить моменты вызовов RHS, якобиана и сброса, а также численную роль `dt` в индексации истории Прейзаха. Для простого прохода по скаляру использовать типизированное обновление. Динамические кандидаты, например `e` вместе с вектором `v`, целиком проверять и преобразовывать на границе параметрического поиска. `Vote` допустим только там, где кандидаты действительно разнородны.

### Локальная передача и общий путь отрисовки

Переименовать роль C++ в клиент, переиспользовав WinSock. Отправка выключена по умолчанию и включается настройкой драйвера. Python принимает подключения на `127.0.0.1`. Одно соединение несёт длину архива как беззнаковое 64-битное число в сетевом порядке байтов, затем ровно указанное число байтов. Префикс позволяет проверить размер и отличить обрыв от полного сообщения. Клиент отправляет и сервер читает в циклах с ограниченным буфером и таймаутами. Верхний лимит должен пропускать измеренную крупную контрольную серию. [Python Socket HOWTO](https://docs.python.org/3/howto/sockets.html#using-a-socket)

Сервер пишет входящую передачу во временный файл, проверяет архив общим загрузчиком, публикует принятый файл и возвращает однобайтовый статус. Статус успеха подтверждает сохранение. После него сервер ставит отрисовку в очередь, а сетевой приём продолжает работать при открытых окнах Matplotlib. Офлайн-команда принимает путь к архиву и вызывает тот же загрузчик и те же обработчики на базе `plotting.py`. Сохранённые ранее JSON/CSV продолжают открываться существующими сценариями или их адаптерами.

## Risks / Trade-offs

- Дополнительные копии больших рядов могут свести на нет пользу NPY. На стороне C++ писать массивы и передавать файл порциями. На стороне Python не собирать архив в один объект `bytes`, читать нужные массивы и измерить пиковую память отдельно от отрисовки.
- Изменение роли текущих и исходных параметров может сдвинуть численный результат. Сравнить эталоны Лоренца, Радонса и гистерезиса и отдельно проверить восстановление параметров, идентичность моделей и независимость двух историй.
- Смысл осей и правила пропусков различаются у старых результатов. Сверять признаки и численные данные через конкретных потребителей, включая пустые массивы, одномерные поля и несимметричные матрицы.

## Migration Plan

1. Пройти весь путь на `JustSolveRodos` с новым архивом и отдельно сверить сохранённый JSON на тех же входах отрисовки. Подключить остальные активные JSON-экспорты и читатели по мере перевода вычислительных API. CSV-сценарии сохраняют путь чтения.
2. Перенести типизированный контекст сначала на Лоренца, затем на Дуффинга и на Радонса с двумя моделями. Обновить вызовы методов анализа, фабрики, параметрические проходы и reset callbacks вместе с их проверками.
3. Проверить, что архив открывается локально при отключённой доставке и после ошибки сети. Снять сравнение JSON и NPY на крупной серии перед завершением миграции.
