# Spec Delta

## ADDED Requirements

### Requirement: Схема аргументов является частью типа системы

Тип системы MUST определять схему параметров при компиляции. Правая часть, якобиан и операции обновления параметров MUST принимать значения этой схемы. Динамические входы из конфигурации и параметрического поиска MUST проверяться до изменения системы и запуска вычислений для кандидата.

#### Scenario: Неверная схема для системы той же размерности

- **WHEN** C++-потребитель передаёт параметры двумерной системы Дуффинга в типизированный интерфейс двумерной системы Радонса
- **THEN** вызов отклоняется при компиляции

#### Scenario: Ошибка динамического кандидата

- **WHEN** кандидат задаёт неизвестное поле, несовместимый тип или вектор неверной формы
- **THEN** граница сообщает, какое значение несовместимо, без частичного применения кандидата и вычислений с ним

### Requirement: Траектории имеют отдельные контексты

Основная и возмущённая траектории MUST получать отдельные значения параметров и независимые экземпляры изменяемой модели Прейзаха, если она используется. Система MUST отклонять операции, задающие общий экземпляр модели двум траекториям или запускающие парное вычисление без возмущённого контекста.

#### Scenario: Независимые истории гистерезиса

- **WHEN** система продвигает или сбрасывает модель одной траектории
- **THEN** параметры, экземпляр модели и накопленная история второй траектории не меняются

#### Scenario: Обеим траекториям передана одна модель

- **WHEN** потребитель создаёт или обновляет пару контекстов и обе ссылки указывают на одну модель
- **THEN** система сообщает об ошибке до интегрирования или изменения действующих контекстов

#### Scenario: Расчёт без второго контекста

- **WHEN** потребитель создаёт валидную систему с основным контекстом и запускает одиночную траекторию
- **THEN** расчёт выполняется
- **AND** запрос парного расчёта с этой системой возвращает ошибку до первого шага

### Requirement: Сброс состояния и восстановление параметров имеют явную семантику

API MUST различать сброс начальных координат и времени, восстановление параметров из значений по умолчанию и обновление самих значений по умолчанию. Действия над моделью при сбросе MUST выполняться для того контекста, которому они адресованы.

#### Scenario: Временное изменение параметра

- **WHEN** вызывающий код меняет текущее значение параметра одной траектории, а затем явно восстанавливает её параметры по умолчанию
- **THEN** исходное значение этой траектории восстанавливается, а значения второй траектории не меняются

## MODIFIED Requirements

### Requirement: Численная сопоставимость экспериментов

При одинаковых исходных условиях, шаге, параметрах и состоянии модели библиотека MUST сохранять численное поведение интегрирования. Для переведённых экспериментов новый архив MUST сохранять смысл полей, формы и порядок отсчётов эталонных результатов. Ранее сохранённые результаты MUST оставаться читаемыми в Python.

#### Scenario: Сравнение с зафиксированным эталоном

- **WHEN** потребитель воспроизводит эталонные расчёты Радонса и Лоренца и параметризованный расчёт петли гистерезиса
- **THEN** формы, порядок отсчётов и смысл экспортируемых полей совпадают с эталоном, а значения укладываются в заданные для этих расчётов допуски

#### Scenario: Повторный запуск расчёта сечения Пуанкаре

- **WHEN** потребитель вычисляет сечение или стробоскопическое отображение для валидной системы
- **THEN** расчёт начинает интегрирование после сброса состояния и завершает вызов с живой системой, состояние которой снова сброшено

#### Scenario: Повторное построение из прежнего результата

- **WHEN** пользователь открывает уже сохранённый файл прежнего формата для переведённого эксперимента
- **THEN** Python восстанавливает исходные данные для соответствующего сценария отрисовки
