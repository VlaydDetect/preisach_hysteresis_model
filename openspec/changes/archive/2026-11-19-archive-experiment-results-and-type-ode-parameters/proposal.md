# Proposal

## Why

Результаты экспериментов собираются через перегруженную обёртку JSON, а крупные численные серии занимают сотни МиБ. Строковые аргументы ODE откладывают проверку типов до вычисления и затрудняют разделение двух историй Прейзаха. Сохранение результата и передача его в Python сейчас идут по разным путям.

## What Changes

- Ввести единый архив результата с JSON-метаданными и массивами NPY. C++ сохраняет его перед любой попыткой отправки. Python строит графики из того же формата при загрузке с диска и при приёме по TCP.
- Добавить опциональный клиент и постоянно принимающий локальный Python-сервер. В архиве передавать стабильный вид графика и небольшой набор параметров оформления, включая заголовок и подписи осей.
- **BREAKING** Перевести численные входы ODE со словаря `DSArgs` на схемы, известные при компиляции. Передавать отдельные контексты основной и возмущённой траекторий с независимыми экземплярами модели Прейзаха. Сохранить динамический ввод на границах конфигурации и параметрического поиска.
- **BREAKING** Перевести затронутые вычислительные API с `JsonDocument` на типизированные результаты. Для типов, которые напрямую не поддерживает `nlohmann::json`, предоставить явные адаптеры. Для переведённых экспериментов сделать архив основным форматом записи и сохранить чтение ранее записанных результатов.

## Capabilities

### New Capabilities

- `experiment-result-archive` — версионированный архив эксперимента, сохранение из C++ и воспроизведение графиков из архива в Python.
- `experiment-plot-service` — опциональная передача сохранённого архива локальному Python-серверу и отрисовка через общий загрузчик.

### Modified Capabilities

- `ode-dynamical-systems` — типизированные параметры, раздельные контексты траекторий и численная сопоставимость при переходе формата.
- `mutcpp-numerical-api` — типизированные результаты и явные JSON-адаптеры с сохранением семантики копирования контекста.

## Impact

- Публичные заголовки MUTCpp в `ODE`, `Json` и затронутых компонентах `Hysteresis`. Драйвер экспериментов, файловый экспорт и клиент WinSock.
- Python-загрузка архивов, `server.py`, офлайн-сценарии и переиспользование функций `plotting.py`.
- Проверки форм и численных эталонов, совместимости сохранённых данных, сетевого обмена и памяти на существующей крупной серии.
