# Spec Delta

## ADDED Requirements

### Requirement: Снимок хранит согласованное состояние системы с Прейзахом

Снимок MUST содержать время, физические координаты и достаточную для продолжения рабочую память всех подмоделей. Снятие снимка, пробный шаг и отклонение пробы MUST сохранять принятое состояние и журнал. Ответвления MUST начинаться в одно физическое время и иметь независимую рабочую память. Неизменяемая мера MAY быть общей.

#### Scenario: Ответвление после прогрева

- **WHEN** из согласованного снимка после прогрева запускают опорную и возмущённую траектории
- **THEN** обе наследуют предысторию до снимка и стартуют в одно время с одной фазой возбуждения
- **AND** продвижение или отклонённая проба в одной копии оставляет состояние и журнал другой копии неизменными

#### Scenario: Возмущение физического состояния

- **WHEN** при ответвлении меняют только скорость
- **THEN** текущий вход и память на момент ответвления остаются прежними
- **AND** при изменении входной координаты модель применяет соответствующий переход к унаследованной памяти

### Requirement: Стандартное интегрирование удерживает выход Прейзаха

Для системы Радонса с Прейзахом режимом по умолчанию MUST быть стандартный RK4 с удержанием принятого выхода. Все стадии MUST получать один `P_n`, а после принятия конечной точки рабочая память MUST обновляться ровно один раз по принятому входу.

#### Scenario: На стадиях получены разные входы

- **WHEN** стандартный шаг получает разные пробные координаты на стадиях `k1`–`k4`
- **THEN** все четыре стадии используют выход, принятый в начале шага
- **AND** выход в новой принятой точке используется на следующем шаге

### Requirement: Стратегия вычисления выхода на стадиях выбирается явно

Если стратегия вычисления выхода на каждой стадии предоставлена, её выбор MUST быть явным. Штатные эксперименты, стандартный интегратор по умолчанию и событийный расчёт спектра MUST использовать удержание выхода.

#### Scenario: Доступна экспериментальная стратегия

- **WHEN** потребитель создаёт систему с настройками по умолчанию или запускает штатный расчёт спектра
- **THEN** интегратор удерживает выход на каждом гладком подшаге
- **AND** вычисление выхода на каждой стадии доступно только по явному запросу потребителя

### Requirement: Событийный интегратор локализует поперечные пересечения

Выбираемый событийный интегратор MUST локализовать первое активное поперечное пересечение в пределах основного шага с заданным допуском времени, разделить шаг, применить переход и пересчитать поверхности перед продолжением. Активные поверхности Радонса MUST включать разворот, стирание сохранённого экстремума, границы носителя и швы двойной модели.

#### Scenario: Поворот или стирание внутри основного шага

- **WHEN** вход разворачивается либо пересекает активный сохранённый экстремум при ненулевой скорости
- **THEN** интегратор завершает подшаг в найденной точке, обновляет память и продолжает с актуальным набором поверхностей

#### Scenario: Касание без пересечения

- **WHEN** функция события касается нуля без смены стороны и перехода ветви
- **THEN** интегратор не регистрирует поперечное событие и не добавляет поворотную точку

#### Scenario: Совпавшие поверхности

- **WHEN** несколько активных поверхностей пересекаются в пределах допуска одного момента
- **THEN** согласованный переход применяется один раз в общем моменте, а следующий подшаг продолжается без повторной обработки того же пересечения

### Requirement: Переход использует односторонние данные

Интегратор MUST использовать соответствующие односторонние значения на обеих сторонах события. Сальтационный переход физических вариаций MUST включаться только при обоснованном скачке физического поля или нетривиальной карте сброса. Скачок наклона при непрерывном поле и тождественном сбросе MUST давать единичный физический переход.

#### Scenario: Скачок наклона при непрерывном выходе

- **WHEN** на границе носителя или шве меняется наклон, а односторонние значения поля совпадают
- **THEN** физическое состояние и его вариация непрерывны в событии, а дальнейший подшаг использует данные новой стороны

#### Scenario: Неподдерживаемый переход

- **WHEN** запрошен расчёт через скачок или сброс, для которого отсутствует обоснованное касательное отображение
- **THEN** расчёт сообщает об ограничении вместо публикации недостоверного спектра

## MODIFIED Requirements

### Requirement: Численная сопоставимость экспериментов

При одинаковых исходных условиях, шаге, параметрах, состоянии модели и выбранной численной схеме библиотека MUST сохранять воспроизводимость интегрирования. Для переведённых экспериментов новый архив MUST сохранять смысл полей, формы и порядок отсчётов эталонных результатов. Ранее сохранённые результаты MUST оставаться читаемыми в Python. Исправление схемы MUST иметь проверенный численный эталон с описанием расхождений.

#### Scenario: Сравнение с зафиксированным эталоном

- **WHEN** потребитель воспроизводит эталонные расчёты Радонса и Лоренца и параметризованный расчёт петли гистерезиса
- **THEN** формы, порядок отсчётов и смысл экспортируемых полей совпадают с эталоном, а значения укладываются в допуски для соответствующей схемы

#### Scenario: Явное удержание в эталоне Радонса

- **WHEN** Радонс рассчитан с явным удержанием вместо прежнего индексного кэша
- **THEN** изменившаяся серия проверяется по эталону удержания и сходимости при измельчении шага, а причина расхождений фиксируется

#### Scenario: Повторный запуск расчёта сечения Пуанкаре

- **WHEN** потребитель вычисляет сечение или стробоскопическое отображение для валидной системы
- **THEN** расчёт начинает интегрирование после сброса состояния и завершает вызов с живой системой, состояние которой снова сброшено

#### Scenario: Повторное построение из прежнего результата

- **WHEN** пользователь открывает уже сохранённый файл прежнего формата для переведённого эксперимента
- **THEN** Python восстанавливает исходные данные для соответствующего сценария отрисовки
